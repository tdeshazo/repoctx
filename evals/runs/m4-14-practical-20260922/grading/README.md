# M4-14 practical paired grading handoff

This working directory grades 66 completed trials: each of 33 M4 tasks once with ordinary tools and once with ordinary tools plus access to repoctx. The run archive is `evals/runs/m4-14-practical-20260922/`; live trial workspaces were under `/tmp/m4-14-practical-20260922/`. The 33 `gold-cards.json` cards are byte-identical to the run archive's frozen copy (SHA-256 `f275145561fa93fb9c919308aaa5d886a6bf37a1ed63e3d32340ace40586af1e`). Task questions, expected outcomes/answers, and permitted source text did not change during grading.

`RUBRIC.md` gives the question-first pass/partial/fail rule. `reviewer-packets/batch-*.json` lists shuffled opaque IDs; each `<id>.json` packet contains the question, gold answer/outcome, original permitted sources, masked model response, and observed source diff. It has no task ID, condition, model, usage, cost, or trial path. The synthetic restricted token was masked in packets. `operator-mapping.json` binds IDs to trials and conditions and must remain separate from reviewer packets. `operator-repository-map.json` is routing metadata only.

Grader A (`gpt-5.6-terra`, high reasoning) wrote `grades/batch-*.json`. Independent grader B (`gpt-6-sol`, high reasoning) wrote `grades/audit-*.json`, auditing every initial nonpass and at least one pass per batch. The root operator recorded three question-first resolutions in `grades/adjudications.json`; initial and audit grades were preserved. `operator-results.json` contains the final joined per-trial results, and `summary.json` contains paired aggregates. Grading was completed before condition labels were joined to scores.

A verified success means final adjudicated grade `pass`, agent exit code 0, no agent timeout, no observed substantive scope violation, and (for change tasks) a passing independent check. Partial never counts as success. Tool-call cap overages, recovered command errors, and unsolicited source edits are reported as audit fields rather than added answer criteria. `change-checks.json` contains 12 evaluator-owned checks run in separate 15-second bubblewrap processes on private copies of the edited trial repositories; verifier time is separate from agent wall time. The checks passed. Source diffs were presented to graders; the two unsolicited edits on a non-change task remain explicit audit flags.

`adoption-audit.json` classifies recorded commands: reading the skill file, `repoctx version`, and successful evidence retrieval are distinct. It asserts 66 distinct trials, 33 complete task pairs, and both conditions per task. The root operator also inspected all 33 treatment command lists; the command scan found no suspect network or evaluator-path access. `scope-findings.json` records the review basis and observed findings, rather than claiming exhaustive proof from absent events.

`command_call_count` is the runner's count of agent shell-command calls; `observed_tool_item_count` counts tool event items. Across 66 trials these are 246 and 260, respectively. A generic command follow-up is any command after a trial's first command (180 total). A repoctx retrieval follow-up is an additional repoctx evidence request after a trial's first such request (0 total). `cached_input_tokens` is a subset of `input_tokens`; do not add them together. Missing usage is `null`, never zero. `wall_seconds` is agent trial wall time and excludes workspace preparation, condition setup, independent checks, grading, and archiving. Token totals are usage measurements, not billed currency costs.

The scripts `make_packets.py`, `check_changes.py`, `audit_adoption.py`, and `join_results.py` are temporary operator helpers with absolute `/tmp` paths. Their JSON results and the run archive are the durable evidence; the scripts are not portable contracts or a replacement for the repository's M4 protocol.
