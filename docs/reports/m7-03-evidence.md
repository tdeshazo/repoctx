# M7-03 evidence: unified artifact authoring and compilation

M7-03 makes `repoctx.artifact-authoring/v1alpha2` the sole authored artifact
input for both canonical compilation and the standalone catalog projection.
`pkg/artifacts.Compile` strictly decodes the semantic declarations, resolves
named anchors beneath the selected root, and returns one validated result.
`repoctx artifacts` derives `repoctx.artifacts/v1alpha1` from that result;
manifest compilation adapts the same result directly into
`repoctx.entities/v1alpha2`. Neither path accepts authored hashes or physical
coordinates.

The canonical entity contract now preserves multiple exact declaration spans
and declared relationships. Artifact sensitivity and stable, same-namespace
owner entity IDs flow into the same entity fields used by manifest components
and Markdown frontmatter. Declared inputs become freshness dependencies, while
their detailed role and required-state claims remain available in the derived
standalone catalog.

Canonical compilation merges manifest components, artifact declarations, and
frontmatter before validation. It sorts semantic output and rejects duplicate
entity identity across any pair of those inputs, including duplicate artifact
declarations, instead of resolving conflicts by source order. Artifact anchor
reads also obey the caller's compile scope.

Evidence is covered by the artifact authoring/adapter tests, manifest merge and
duplicate-identity tests, repository IR validation, JSON Schema conformance,
relocation-stability tests, and root dogfood regeneration checks. The committed
dogfood and evaluation catalogs are generated by `repoctx artifacts`; agents do
not author their hashes or coordinates.
