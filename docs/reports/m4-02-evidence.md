# M4-02 comparison-condition evidence

Date: 2026-09-21

## Outcome

The M4 harness now exposes six distinct, bounded condition inputs:

| Condition | Supplier | Attribution |
| --- | --- | --- |
| `ordinary_tools` | filesystem listing, search, and reads | no preselected evidence |
| `bounded_lexical` | independent Python lexical windows | no repoctx |
| `repoctx_no_graph` | repoctx context bundle, depth 0 | repoctx |
| `repoctx_graph` | repoctx context bundle, depth 1 | repoctx |
| `artifact_aware` | declared catalog spans selected by the harness | repository curation, no repoctx claim |
| `human_oracle` | evaluator-owned required evidence spans | human gold, no repoctx claim |

The registry validator rejects missing, extra, or mislabeled conditions. All
rendered inputs use a 12,000-byte envelope with explicit availability,
omissions, curation, and measured serialized bytes. The oracle excludes denied
evidence and expected answers. Artifact catalogs are generated by `repoctx
artifacts`; the Go dogfood test rejects stale generated catalogs.

Only `ledger-lite` has a declared catalog in this pilot. Other repositories
report the artifact-aware condition as unavailable, keeping that subset visible
instead of substituting a different retrieval method.

## Checkout smoke

A checkout-built repoctx binary rendered `l-cross-quote` from a fresh export at
both declared graph depths. Depth 0 produced a 9,026-byte envelope with three
symbols and six relationships; depth 1 produced 9,072 bytes with four symbols
and seven relationships. This confirms that the harness invokes distinct graph
settings and accepts their real contract output. It is not a task-quality or
performance comparison.
